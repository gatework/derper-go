# 模块设计与渐进审查

## 领域边界

| 模块 | 负责 | 不承担的工作 |
| --- | --- | --- |
| `config.Config` | 用户意图、严格 JSON 解析、字段错误 | 网络发现、凭据、运行状态 |
| `config.Settings` | 一次性解析默认值、地址和绝对路径 | 重新选择端口或区域 |
| `setup.Workflow` | 初始化分流、输入需求、只读预检、安全摘要、批准和可恢复安装 | 终端渲染、修改 Tailnet 策略、管理旧服务 |
| `relay.Server` | 上游 DERP/STUN、监听、关闭、接收就绪信号 | Cloudflare、ACME、配置文件 |
| `tailnet.Verifier` | 通过现有 tailscaled 查询节点、登录状态和区域 | 嵌入 tsnet 或接管 tailscaled |
| `certificate.Renewer` | ACME 账户、DNS-01、续期、重试和 TXT 清理 | 地址记录发布 |
| `certificate.Store` | 证书解析、持久化、不可变 TLS 快照 | 握手时读文件或访问网络 |
| `dns.Publisher` | A/AAAA 差异、所有权、批准接管、故障恢复 | ACME TXT |
| `cloudflare.Client` | 有界 HTTP API 与具体 RecordUpdate 类型 | 用户交互、进程退出 |
| `state.Store` | 进程写锁、节点身份及原子状态文件 | 配置默认值 |
| `systemd` | 独立用户、单元、凭据、安装、就绪通知 | 业务协议 |
| `daemon` | 组合与生命周期、组件健康、DERPMap 导出 | 交互初始化 |
| `cli` | 命令参数、中文终端输入与展示、确认渲染、命令退出码 | 解释初始化日志阶段、比对部署来源 |

选择本机 tailscaled 而非嵌入 tsnet，保留已有 Tailnet 身份和部署边界。私有中继通过上游准入 hook 使用 `VerifyNode(ctx, key)`，本地查询三秒超时；关闭会取消未完成查询。未知节点、不可用 tailscaled 和超时均拒绝接入。

## 默认配置

原配置同时暴露监听字符串、文件布局、证书选项、DNS 管理模式和区域内部结构。重构后默认配置仅包含域名和邮箱，其他值是显式覆盖项。Go 中分别使用意图结构和解析后的 Settings；证书及 DNS 接收领域 Options，不依赖整份用户配置。

自动发现只在有明确生命周期的位置发生：初始化选择端口和空闲区域并保存，DNS 维护周期发现当前 IPv4。运行时不重新选择端口或区域。IPv6 需要显式地址，避免发布不可达 IPv6；动态 IPv4 的 DERPMap 使用域名解析。

## 初始化入口

`setup.Workflow.Initialize(ctx, Request, Interaction)` 是唯一的初始化编排入口。`Request` 保存调用意图：配置和状态路径、部署模式、显式设置、文件来源、预览、是否允许交互，以及分别表示安装批准和 CA 条款接受的 `Consent`。`Overrides` 使用具体类型的指针区分省略与显式的 `false`、`0` 或空字符串；未指定的字段保留已有配置。

交互边界只有 `Read`、`Show`、`Confirm`。Workflow 决定何时需要域名、邮箱或凭据，何时展示摘要及询问批准；CLI 负责中文提示、隐藏 Token 输入、终端取消和结果渲染。摘要是独立副本，不包含凭据、节点私钥或可修改的执行计划；控制器地址隐藏查询参数。执行计划、预检、写入及 prepared 恢复均为 setup 私有实现。

| 已有部署 | 初始化行为 |
| --- | --- |
| 无安装日志 | 合并显式设置；按需输入；预检、展示、确认后安装 |
| `approved` 等未完成阶段，无运行锁 | 继续原有准备流程，仍执行发现和预检；配置缺失时使用日志中的配置 |
| 未完成阶段，有运行锁 | 返回运行状态，不重新准备 |
| `ready` / `prepared` 且预览 | 仅核对显式设置和来源，返回当前阶段 |
| `prepared` 且要求安装并启动服务 | 核对已批准配置和本地依赖、刷新单元并启动；不重复发现或安装，不读取省略的来源 |
| `ready`，或 `prepared` 且仅准备服务/前台配置 | 保留部署并返回状态 |

文件来源优先级保持为显式 Token 文件、配置指定文件、已存在的受管文件、环境变量、交互输入；重复初始化时只读取显式来源。配置内的相对路径仍以配置目录为基准，命令提供的来源与手动证书路径以工作目录为基准。生产服务固定使用标准路径；测试用私有的临时主机目录替代它，避免修改可执行计划来绕过服务路径验证。

自动化缺少安装批准或所需条款接受时，在读取凭据及网络发现前失败。交互模式保持一次合并确认；预览不询问安装批准，也不写入或恢复部署。保存顺序、安装锁与运行锁交接、重试策略及迁移服务边界沿用原实现。

## 写入与恢复顺序

1. 只读检查 tailscaled、区域、地址、Cloudflare 记录及 CA 条款。
2. 显示摘要，用户确认。自动化的安装批准与 CA 条款接受使用不同开关。
3. 排他安装锁和运行状态锁，重新核对确认时的配置。
4. 保存批准记录，再保存凭据、配置与身份，安装独立服务。
5. 释放运行锁，启动守护进程；守护进程先绑定全部监听，再取得有效证书。
6. TLS 接收循环就绪，发送 systemd READY，然后启动 DNS 发布与健康检查。
7. DNS 或 tailscaled 异常单独显示；DNS API 故障保留可用中继并退避重试。

状态写入使用同目录临时文件、权限设置、fsync、原子 rename 和目录 fsync。排他创建使用硬链接发布，避免失败时留下半文件。身份、证书与 DNS 请求日志分别持久化；修改状态的离线操作与守护进程互斥。

DNS 接管保存用户确认时的完整业务记录快照，写入前检查 ID、类型、名称、地址、TTL、代理和注释。任何外部变化都阻止接管；已有所有者注释、多条同类型记录和 CNAME/NS 冲突拒绝自动处理。丢失创建或更新响应通过 pending 日志恢复，不盲目重复创建或覆盖。

## 本轮审查与改进

- 原证书、DNS 和应用命名及整个 Config 传递掩盖了领域边界：拆分为 Renewer、Store、Publisher、Verifier 和 daemon，HTTP 更新使用具体类型。
- 原向导只生成大量配置：改为最小意图、隐藏凭据、一次安装摘要确认、独立凭据与条款文件，并提供非交互明确开关。
- 原安装流程依赖手工用户和目录：新增独立服务用户、受保护文件、原子二进制安装、可恢复阶段及运行锁交接。
- 配置变更也可能影响 systemd 权限和凭据来源：`service start/restart` 根据当前配置刷新受管单元后再执行操作，避免低端口权限或 Token 路径停留在旧值。
- 单纯进程启动不等于服务可用：新增真实接收循环就绪、Type=notify 和证书/DNS/Tailnet 独立状态。
- 历史状态可能在崩溃或 PID 复用后误报健康：读取时核对锁、启动标识和进程启动时间，并拒绝过期就绪快照。
- 网络和终端取消可能留下阻塞工作：API、发现、准入有界超时；终端使用轮询取消，无遗留读 goroutine，隐藏输入在退出时恢复终端。
- 原 DNS 接管由手写记录 ID 授权：改为预览、批准快照、全部验证后再开始写入；保留 TXT 隔离与响应丢失恢复。
- 测试补齐安装故障恢复、确认后的配置变更、凭据写入失败、重复初始化、过期状态、区域冲突和 DNS 故障保留中继；真实服务安装与重启在隔离 systemd 容器验证。

协议保持由 Tailscale 库负责，原生及 WebSocket 转发、STUN 事务与映射地址、MetaCert、SNI 和证书热更新继续通过原有回归测试。
