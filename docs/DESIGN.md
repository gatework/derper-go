# 设计与审查记录

## 组成

CLI 负责参数与输入输出，config 负责纯校验，app 组合生命周期。relay 复用 tailscale.com/derp/derpserver 和 net/stunserver；certmgr 管理 ACME；cloudflare 仅处理 API；dns 独立管理 A/AAAA；state 负责进程锁与身份持久化。

参考 AnyTLS 的 certmgr/fileio 实现及测试迁移并保留 MIT 版权。DNS 地址同步已从证书维护移出，DNS-01 TXT 始终只服务于一次授权流程。

## 运行约定

- 先校验与获取状态锁，再绑定所有配置的端口；证书就绪后启动中继与地址维护。
- 有效缓存允许离线启动。获取证书回调仅读取内存，不执行网络或文件 I/O。
- 证书发布前校验密钥对、域名、用途与时间；不可变快照经上游 MetaCert 包装后提供握手。
- 控制面失败保留仍有效的证书和地址。首次无证书且签发失败时返回错误。
- 关闭监听、取消维护任务、关闭上游 DERP 的 hijacked 连接并等待 worker 退出。停机使用独立的超时上下文。
- Cloudflare 响应限长，错误只包含状态码和错误编号，不包含上游回显正文。凭据在请求时重新读取。

## 本轮审查修正

| 问题 | 修正 | 回归测试 |
| --- | --- | --- |
| 原证书同步脚本分别替换 cert/key 且依赖重启，存在中间状态与加载状态脱节 | 完整 bundle 原子落盘后发布内存快照，续期不重启服务 | ACME TLS 热更新、旧 DERP 连接连续收发 |
| PATCH 已提交但响应丢失会被误判成外部修改 | 先匹配持久化的未完成操作，精确恢复记录 ID 和内容 | 丢失 create/update 响应的恢复与幂等 |
| 有效缓存启动前读取凭据可能使暂时的凭据问题中断服务 | 缓存先投入使用，凭据检查归入控制面请求 | 无凭据、有有效缓存的启动 |
| 上游直接本机鉴权的 HTTP 请求没有超时，原生 Handler 又脱离请求上下文 | 使用上游准入接口连接仅回环监听的适配器，本机查询限制 3 秒并随生命周期取消 | 未知、不可用及无响应 tailscaled；停机取消 |
| CA 限流在进程重启后可能失去退避 | Retry-After 持久化，离线强制续期也遵守窗口 | 重启后的退避保留 |
| 主服务与离线管理命令并发写状态 | 进程级排他锁；只读命令保持无写入 | 第二写入者拒绝与释放后重获 |
| systemd 凭据路径局部加引号会被忽略，verify 仅警告仍返回成功 | 对完整 ID:PATH 加引号；CI 将校验诊断视为失败 | 真实 systemd-analyze 校验生成单元 |

## 明确的首版边界

单实例、单域名、Linux amd64/arm64；支持 Cloudflare DNS-01 和手动 TLS。DNS-01 CNAME 委派、通配符、DERP mesh、远程策略发布及 systemd socket activation 不属于首版。

后台可自动创建新地址记录，接管已有记录需要显式 ID。未配置的地址族不自动清理。DNS API 不提供跨请求事务；本地日志用于恢复单个操作，外部并发编辑通过冲突检查报告，操作方仍需维持单一管理者。

私有验证只约束 DERP 客户端准入。STUN 按上游设计响应公网绑定请求；已有通过准入的连接不会因后端短暂故障被立即撤销。实际 tailnet 转发仍应在部署阶段由已授权设备验证。
