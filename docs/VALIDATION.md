# 验证范围

## 本地回归

```sh
go test ./...
go vet ./...
```

低资源开发机可设置 `GOMAXPROCS=2 GOMEMLIMIT=200MiB`，并为 `GOTMPDIR` 指定磁盘上的临时目录，使用 `-p 1`。测试不读取生产 Token，不向真实 ACME 或 Cloudflare 发起写请求。

覆盖：

- 统一结构的严格配置、最小 JSON、默认值和显式关闭、路径解析与无副作用检查。
- 真实本地 HTTP ACME/Cloudflare 假服务：签发、续期、重启、TXT 清理、取消、响应丢失和持久化 Retry-After。
- 证书原子更新、有效缓存无凭据启动、短期证书续期调度、SNI 与过期拒绝。
- 原生 DERP/WebSocket 转发、TLS MetaCert、STUN 事务和地址、准入超时与关闭取消。
- DNS 归属、批量接管验证、确认快照变更、外部修改与删除、丢失响应恢复、地址发现失败保留记录。
- 初始化只读预检、选择结果保存、显式条款、磁盘写入失败、安装失败恢复、排他运行锁交接、取消与 EOF。
- 重复初始化保留配置与身份，过期状态及 PID 复用不误报就绪，DNS 故障时 TLS 中继继续工作。

## CI

CI 运行格式和模块检查、全量 race、go vet、govulncheck、两个 Linux 架构的原生构建/运行、发行包及许可证检查。amd64 归档重建后逐字节对比；普通 CI 保留归档，标签发布复用同一份受检附件。`golang.org/x/net` 固定 v0.62.0；此前检查发现的 GO-2026-5932 位于未被本项目导入的 `x/crypto/openpgp`，应继续以 CI 的可达性分析为准，不能把模块存在等同于已构建程序受影响。

systemd 作业下载同次工作流的 amd64 发行包，并构建独立 Ubuntu 容器，在容器内真实执行 `init`、`service restart/stop/start`，核对服务用户、目录与密钥权限、Type=notify、443 占用时保存 8443、修改端口后重新生成权限、实际 TLS 探测、重复初始化和节点身份保留。使用本地自签测试证书、公开准入与关闭 DNS，避免使用真实云凭据。自动 ACME、Cloudflare 和私有准入分别由对应本地假服务测试验证。

容器测试脚本位于 `integration/systemd.sh`，要求专用标记文件和环境变量。不要在宿主机或生产机执行该脚本。完整测试环境由 `.github/workflows/ci.yml` 创建和销毁。

## 生产验证边界

本轮不进行 la3 切换，不停止旧 DERP/AnyTLS 服务，不改变生产 DNS。CI 的协议与服务验证不等同于跨公网的 Tailnet 转发验证。正式切换仍需按部署文档安排窗口，并从两台授权 Tailnet 设备确认真实 DERP 数据转发。

## Release 回归

`python3 -m unittest discover -s scripts -p 'test_*.py' -v` 验证版本格式、归档路径与类型、完整 SHA、ELF 架构、动态加载器拒绝、缺失架构、旧包混入，以及发布时的 API 错误、上传响应丢失、草稿恢复、标签移动、已公开附件防覆盖和预发布状态。发布脚本通过临时假服务接口运行这些测试，不创建真实 Release。

工作流由固定版本的 actionlint 校验。正式标签还经过完整 CI、GitHub 来源证明和上传回读；只有附件内容及远端标签再次核对成功后才公开草稿。流程和重试方法见 [RELEASING.md](RELEASING.md)。

## 并发与性能验证

新增的准入、心跳及取消测试使用 `testing/synctest`，覆盖共享查询中的单个调用者取消、完成后重新验证、3 秒总预算、128 个请求上限、服务关闭与配额回收。真实网络测试检查已升级 DERP 连接仍占用连接额度。ACME 测试验证 TXT 清理失败不丢弃有效证书、清理等待窗口跨重启保留，外部修改继续拒绝删除。

CI 增加 Staticcheck v0.8.2（支持 Go 1.27）、配置与 Retry-After 模糊测试，以及独立进程中 100 个真实 DERP 连接的短时回归。完整版通过 `Relay performance` 手动工作流执行，默认基线 `b984078e8d2cd0fbd84dfdcc09137b53eeed62c4`，1,000 个连接、每版本每轮持续转发 600 秒，共三组同机成对试验。偶数轮交换执行顺序。

性能服务端限制为 2 CPU / 2 GiB，客户端使用另外两个 CPU；只使用临时自签证书、模拟本地 tailscaled 和关闭 DNS 的配置。模拟服务只测试准入接口及故障边界，不代表真实控制面的网络性能。首轮额外覆盖空闲、慢接收端（32 对连接，每对每秒发送 500 包、接收端每 100 毫秒读取一包）、突发重连、tailscaled 延迟与恢复；分别采集 96 MiB、256 MiB Go 内存预算下的表现。CPU/heap/allocs/mutex/block 分析单独执行，不混入吞吐门禁。

每组附件保留源提交、CPU 型号、吞吐、单向转发 P50/P95/P99、CPU 时间、RSS、累计分配、GC、FD、goroutine 及冷却后的资源状态。连接池允许按正常空闲期限回收。相对吞吐的中位数小于 0.95 或 P99 比值的中位数大于 1.10 时失败；应检查原始数据并重复成对试验，不能仅取最好一次。故障、内存预算与 profiling 场景必须全部完成才能通过交付门禁。可启用 `resilience_only` 单独调试这些场景；完整验收仍运行全套。采样独立于负载计时，失败次数写入报告，过多采样失败会阻止通过；内核 MaxRSS 用于补充瞬时 RSS 采样。实际数据以工作流附件为准，未跑完前不声明达到性能目标。

压测工具 `integration/relayload` 与脚本只用于一次性 CI 主机，不随发行包提供，不得在生产主机运行。完整工作流为 `.github/workflows/performance.yml`。


配置与协议回归同时覆盖：IPv4/IPv6 绑定、HTTP 端口冲突、时间单位和显式 0、连接突发/回填、完整控制器来源 IP、明确拒绝与故障放行的区别、取消、重定向拒绝、Mesh 双向跨节点转发与关闭、密钥凭据快照、bootstrap 隐藏域名与百分比、解析故障保留缓存、有效配置输出后重新读取。实验性上游字段不在本轮范围。

准入并发以客户端查询生命周期的 `admission.peak_running` 为门禁依据，同时保留模拟服务的峰值处理数。HTTP 超时取消后，服务端可能尚未收到连接关闭通知，因此模拟处理器的瞬时数量可能包含已取消请求，不能直接等同于仍在运行的客户端查询。


v0.2.0 的额外回归覆盖原身份导入、区域域名/端口匹配、拒绝覆盖已有身份、组合准入的短路拒绝与共享额度、控制器在途请求策略快照，以及通过私有控制 socket 进行实际 TLS/DERP 连接重载。隔离 systemd 测试核对 reload/SIGHUP 后 PID 保持、无效配置被拒绝、首次升级仍能正常 restart。不新增监控或指标接口。


本轮新增回归包括：发送前失败不留下待恢复写入、不确定写入优先于取消、整个分页响应预算、错误读取不泄露正文且保留 Retry-After、已知 TXT 的权威不存在证明、借入 Transport 不被关闭、初始化显式来源校验、prepared 预览不恢复、重载配置路径匹配、预览响应必要字段以及并发重载关闭取消。字段差异映射覆盖全部 Settings 字段。

常规 CI 记录 Cloudflare 记录查询及连接配额的 benchmem；完整性能工作流第 1 轮先以相同 fixture 做五组成对控制面基准，再执行独立的中继压测。控制面数据用于披露校验成本，DERP 吞吐与 P99 使用上述硬门槛。打包测试同时验证干净源码快照、忽略凭据排除、链接拒绝，以及外部 GOWORK/GOFLAGS 不影响重建结果。
